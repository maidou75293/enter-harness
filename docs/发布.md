# 发布流程

> 目标：源码、wheel、sdist、Git tag、PyPI 元数据一次对齐。

## 1. 改版本（只改一处）

```text
enter_harness/_version.py      # __version__ = "x.y.z"
```

`pyproject.toml` 用 `dynamic` 从这里读；`tests/test_version.py` 会校验源码、
发行元数据、已安装包三者一致。

## 2. 跑验证

```bash
python -m unittest discover -s tests -p "test_*.py"
python tests/e2e_harness_storage.py --backend sqlite
```

公开仓基线应全绿；PostgreSQL 用例在设置 `HARNESS_PG_DSN` 后才运行。

## 3. 构建

```bash
pip install build twine
python -m build --sdist --wheel
twine check dist/*
```

## 4. 发布到 PyPI（需要 token）

```bash
export TWINE_USERNAME=__token__
export TWINE_PASSWORD=pypi-****          # 不要把 token 写进仓库
twine upload dist/enter_harness-x.y.z*
```

没有 token 时只发 GitHub tag：

```bash
git tag -a vx.y.z -m "vx.y.z"
git push origin main vx.y.z
```

## 5. 发布后核对

```bash
pip install --no-cache-dir enter-harness==x.y.z
python -c "import enter_harness, importlib.metadata as m; \
print(enter_harness.__version__, m.version('enter-harness'))"
```

两者必须相同；宿主健康检查直接用 `enter_harness.__version__`。
