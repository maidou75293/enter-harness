# 流式断连回归：确认不留悬挂的模型连接

> 适用：宿主自己消费 `ModelPort.stream()` 或 provider 的 `chat_stream()`，
> 客户端断开（浏览器关闭、SSE 连接重置）后需要立刻停止上游模型请求。

## 1. 内核做了什么

同步 `ProviderModelPort.stream()` 背后是「后台线程跑异步生成器 + 队列转发」：

- 消费方提前退出（`break` / `close()` / 抛异常）时，`_iter_sync` 的 `finally`
  会 `stop.set()`，生产端停止取数，并 `await agen.aclose()`；
- `aclose()` 会触发 provider `chat_stream` 里的 `finally`，`async with
  client.stream(...)` 随之关闭 HTTP 连接；
- 队列有界（128），生产端 put 带超时并检查 stop，不会无限堆积。

代码位置：`enter_harness/llm/sync_model.py` 的 `_iter_sync`
（第 53 行起）与 `ProviderModelPort.stream`（第 241 行起）。

## 2. 回归测试模板（内核里实际用的写法）

`tests/test_llm_registry.py::StreamCleanupTests` 用一个「无限流」provider
模拟上游，消费一块后立刻关闭，断言 provider 的 `finally` 被执行：

```python
class SlowStreamingProvider(FakeProvider):
    def __init__(self, **options):
        super().__init__(**options)
        self.closed = False
        self.emitted = 0

    async def chat_stream(self, messages, tools=None, **kw):
        try:
            for _ in range(1000):
                self.emitted += 1
                yield {"content": "x", "tool_calls": None, "done": False}
                await asyncio.sleep(0.01)      # 模拟慢上游
        finally:
            self.closed = True                 # 等价于 HTTP 连接关闭


def test_early_close_stops_background_stream(self):
    register_provider("slow", lambda **kw: SlowStreamingProvider(**kw))
    model = create_model("slow")

    stream = model.stream([Message(role="user", content="hi")])
    assert next(stream).content == "x"         # 客户端已经收到第一块
    stream.close()                             # 客户端断开

    deadline = time.time() + 3                 # 给清理留出上限
    while time.time() < deadline and not model.provider.closed:
        time.sleep(0.02)
    assert model.provider.closed, "后台异步生成器未关闭"
    assert model.provider.emitted < 1000       # 没有继续拉完整条流
```

## 3. 「客户端 3 秒后断开」怎么模拟

不必真的睡 3 秒（会拖慢回归）。把「3 秒」当成**清理截止时间**，断开本身
用一次显式 `close()` 表示：

```python
stream = model.stream(messages)
first = next(stream)                  # 1) 收到首块，开始计时
# ... 宿主把 first 写给客户端 ...
time.sleep(3)                         # 2) 模拟客户端 3 秒后才断开（可注入）
stream.close()                        # 3) 断连信号
wait_until(lambda: provider.closed, timeout=3)   # 4) 3 秒内必须清理完
```

建议断言两件事，缺一不可：

1. `provider.closed is True`（上游 HTTP 流关闭）；
2. `provider.emitted` 不再增长（没有后台继续消费 token）。

## 4. 宿主是「后台线程 + 队列推流」时

关键不是队列，而是**谁负责关闭同步生成器**。推荐结构：

```python
def produce(stream, out_queue, stop):
    try:
        for chunk in stream:
            if stop.is_set():
                break
            out_queue.put(chunk)
    finally:
        stream.close()          # ★ 必须显式关闭，不能只 break/return

def on_client_disconnect():
    stop.set()                  # 让生产循环尽快退出
    # 若正在阻塞在 out_queue.put，可放入一个哨兵唤醒
    out_queue.put(None)
```

要点：

- `for ... in stream` 循环被 `break` 时，生成器不会自动执行 `finally`；
  必须在 `finally` 里 `stream.close()`（或用 `contextlib.closing`）；
- 关闭后等待一个截止时间再断言，不要用固定 `sleep` 猜测；
- 如果同时用了 `RunHandle.cancel()` 或 provider 的取消令牌，断连和取消
  两条路径都要各写一条回归；
- 断连后重新建立 SSE，应能看到新一轮 `run_id` / 请求，不复用旧的半截流。
