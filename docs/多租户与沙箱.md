# 多租户与沙箱（2026-10-14）

> 本文记录「多租户改造 + 沙箱隔离」的设计、配置与实测结果。
> 目标：**租户之间数据不串、凭证看不见、删除/越狱/外传可控**。

## 1. 总览

**隔离档（`iso_mode`，按租户选）× 网络档（`net_mode`，按租户选）**，两者正交：

| 隔离档 | 边界 | 状态 |
|---|---|---|
| `bwrap` | 进程沙箱：只读系统 + 工作区可写 + 遮宿主数据目录（共用宿主内核）| ✅ 默认 |
| `docker` | 容器：namespace + cgroup + 独立 rootfs | ✅ 已开通 |
| `microvm` | Kata microVM：**containerd + Kata V2 shim，独立内核**（KVM）| ✅ 已开通 |
| `none` | 不隔离（仅排障）| ✅ |

| 网络档 | 含义 |
|---|---|
| `off` | `--unshare-net`，完全断网 |
| `whitelist` | **DNS 白名单**：沙箱内只解析白名单域名（`/etc/hosts`）+ 空 `resolv.conf` |
| `all` | 不限制 |

**后端不可用时自动回退**：请求 `docker`/`microvm` 但环境不具备 → 落到 `bwrap`（并在日志/接口回报实际后端）。

## 2. 数据模型

```
tenants(tid, name, created, status, allow_net, note, reviewed,
        mcp_servers, net_mode, net_allow, iso_mode)
sessions(..., tenant_id)        -- 老库自动 ALTER 补列，默认 'default'
memory(..., tenant_id)          -- 记忆按租户过滤
```

- `status`：`pending`（注册默认）/ `active` / `rejected` / `disabled`；非 `active` 调 `/api/chat` → **403**。
- 兼容：`net_mode` 为空时按 `allow_net` 推（0=`off`，1=`all`）。

## 3. 目录结构

```
~/tenants/<tid>/
    workspace/     ← 沙箱内唯一可写目录（工具读写、命令 cwd、产物落盘）
    uploads/       ← 上传
    skills/        ← 该租户私有技能（与全局 skills/ 合并，同名以租户为准）
    handbook/      ← 该租户工作手册（AGENTS/SOUL/USER/IDENTITY/MEMORY）
```

⚠️ **必须放在 `agent-arch/` 之外**：沙箱要把 `agent-arch/data` 整块遮掉做凭证隔离，
工作区若在 `data/` 底下会一起被遮住。首次启动自动迁移（`tenants.migrate`）。

## 4. 关键配置（`config` 表）

| 键 | 默认 | 说明 |
|---|---|---|
| `sandbox.enabled` | `true` | 沙箱总开关 |
| `sandbox.rw_paths` | `/tmp,/mnt/c` | 额外可写目录（Windows 互操作需要）|
| `workspace.root` | `~/tenants/default/workspace` | 默认租户工作区（迁移后自动指向新位置）|
| `AGENT_TENANTS_DIR`（env）| `~/tenants` | 租户根目录 |

## 5. 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/tenants` | 租户列表（含 status / allow_net / net_mode / net_allow / mcp_servers / iso_mode / 会话数）|
| POST | `/api/tenants` | 注册租户 → 默认 `pending` + 禁网 |
| POST | `/api/tenants/{tid}/review` | 审核与权限：`{action, allow_net, net_mode, net_allow, mcp_servers, iso_mode, note}`；`action=set` 只改权限不动状态 |
| GET | `/api/sandbox/backends` | 隔离后端清单 + 可用性（前端置灰不可用项）|
| GET/POST | `/api/tools/risk` | 工具安全级别（免审 / 需审核，支持前缀·后缀·全通配，含 MCP）|
| GET | `/api/approvals?status=&tenant=` | 审批单列表（含 `expires_at`）|
| POST | `/api/approvals/{aid}/decide` | 裁决：`approve\|reject\|revoke`（可带 `days`）|

前端：侧栏「🏢 租户」→ 注册表单 + 租户卡片（状态徽标 / 允许外网 / **隔离档** / **网络档** / 白名单 / MCP / 通过·驳回·停用·启用）。

## 7. 启用 docker / microVM（需环境动作，等价提权）

> 步骤是**环境**动作，需管理员执行（本机 2026-10-14 已执行）。

**C1 · Docker 容器档**
```bash
usermod -aG docker administrator        # ≈给服务 docker 级权限
# 生效需重新登录 / 重启服务进程（属组在进程启动时固定）
```
风险：docker 组 ≈ root（能挂宿主目录、`--privileged`）。若不接受，保持 `bwrap`。

**C2 · microVM（Kata，走 containerd）**

关键背景：**Kata 2.0+ 的 `kata-runtime` 已删除 OCI 运行时 CLI → Docker 不支持
`--runtime kata-runtime`**（3.x/4.x 实测 `Invalid command "create"`）。官方路径是
**containerd + Kata V2 shim（`io.containerd.kata.v2`）**，不经 Docker。

一次性环境步骤：
```bash
# 1) 装 Kata 到 /opt/kata（官方 static 包：shim + QEMU + 独立内核 + rootfs）
#    kata-static-4.2.0-amd64.tar.zst + kata-go-static-4.2.0-amd64.tar.zst
#    （Kata 4.x 静态包只带 runtime-rs 的 shim；Go shim/kata-runtime 在 go-static 包里）
# 2) 让 containerd 找得到 shim
ln -sf /opt/kata/bin/containerd-shim-kata-v2 /usr/local/bin/containerd-shim-kata-v2
# 3) containerd 2.x 的 ctr 客户端解包镜像需要挂载/DAC 权限（服务非 root 的补偿）
setcap cap_sys_admin,cap_dac_override+ep /usr/bin/ctr
# 4) 服务用户能访问 containerd socket
chown root:docker /run/containerd/containerd.sock && chmod 660 /run/containerd/containerd.sock
# 5) 备好底包镜像（代码也会自动补：docker save | ctr import）
docker save ubuntu:24.04 | ctr -n agentarch images import -
# 6) 之后在租户页把「隔离档」选 microvm 即可（代码无需改动）
```
注意：
- `/dev/kvm` 必须存在（本机有嵌套虚拟化，✅）；宿主 WSL 内核 6.18.33.2，Kata 独立内核 6.18.35。
- **第 3、4 步是补偿性环境设置**：containerd 升级后 `setcap` 会失效、socket 属组会重置，需重设。
- 用的 Docker 仅是「镜像导出器」（`docker save`），microVM 调用链**不含 Docker**。

## 8. 租户配额（在审核环节分配）

| 字段 | 含义 | 执行点 |
|---|---|---|
| `quota_calls_day` | 每日调用次数上限 | `/chat` 入口拦（按当天用户消息数，跨会话）→ **429** |
| `quota_disk_mb` | 工作区磁盘上限 | 写文件前算「已用 + 本次写入」；shell 写入为启发式（10s 缓存）|
| `quota_cpu_sec` | 单条命令 CPU 秒上限 | 沙箱内 `ulimit -t` |
| `quota_mem_mb` | 单条命令内存上限 | 沙箱内 `ulimit -v`（**限于虚拟地址空间**，对 node/python 偏严，按需调）|

`0` = 不限制。分配方式：租户页上的四个输入框，或 `POST /api/tenants/{tid}/review` 带 `{"action":"set","quota":{...}}`。

实测：`cpu_sec=2` → 忙循环 2.0s 被杀；`disk_mb=1` → 写 2MB 被拒、小文件正常；调用次数按当天统计。

## 9. 调用审计与两级审批

### 9.1 审计（`audit_log`）
每次**工具调用**落一条：`tenant_id / session_id / run_id / kind(tool|policy) / name / args(截断) / decision(allow|deny|needs_approval|error) / detail / dur_ms / backend(实际沙箱后端)`。审计写失败**不拖垮主流程**。
查询：`GET /api/audit?tenant=&kind=&decision=&limit=`（返回 `audit` + `stats`）；前端「📋 审计」页。

### 9.2 审批（`approvals` + 指纹）

模式：租户字段 `approval_mode`（chat 请求里可用 `approval_mode` 临时覆盖）：

| 模式 | 行为 |
|---|---|
| `off` | 不审（除非全局 `policy.approve_dangerous=true`，则退化为 `user`）|
| `user` | **用户级 = 信任该用户**：批准一次 → 写「租户通配白名单」→ 该租户**所有**敏感操作全放行（带时效）|

> 历史值 `task`/`both` 一律归并为 `user`。

**判定顺序**（`Policy.check`）：
1. `policy.tools_enabled=false` → 拒；
2. 工具安全级别 = `safe` → 放行（见下）；
3. **超级用户**（`tenants.is_super`）→ 放行（见 §9.3）；
4. 命中「租户通配白名单」`user\|<tid>\|*`（未过期）→ 放行；
5. 命中「按工具白名单」`user\|<tid>\|<tool>`（未过期）→ 放行；
6. 否则开审批单（`pending`，scope=`user`，指纹 `user\|<tid>\|<tool>`，**不含 args**）。

**工具安全级别**（配置 `policy.tool_risk`，JSON）支持：精确名（`shell`）、
前缀通配（`mcp__demo__*`）、后缀通配（`*_write`）、全通配（`*`）；含 MCP 工具。
未配置则回落到代码里的 `danger` 标记。接口 `GET/POST /api/tools/risk`；前端「🛡 工具安全」页。

**裁决**：`POST /api/approvals/{aid}/decide` `{decision: approve|reject|revoke, days?}`（也写审计）。
- `approve`：scope=`user` 时**同时写「租户通配白名单」**（→ 全放行）；授权时效 `days`，
  不传取租户 `approval_days`（默认 **9999** 天 ≈ 永久）→ 写 `expires_at`；同指纹的其它 pending 单一起放行。
- `revoke`：从白名单撤下（`revoked`）→ 之后又会挂起。
- **严格按工具**：一次批准只放行**该工具**（租户+工具指纹）。已**移除**「批一个=放行所有」的批量逻辑（`store.py` 有注释）。

**授权有效期**：指纹匹配只看**未过期**的（`expires_at IS NULL OR expires_at > now`）。
租户页「**时效(天)**」设默认；单次可在待审批卡片填「有效期(天)」（留空 = 用租户默认）。

**挂起 → 审批 → 自动续跑**：需审批时 `pending_resume` 保存现场；批准后自动续跑，拒绝 → 关挂起 + 提示「审核被拒绝，任务已停止」。
ReAct 节点遇 `pending` **立即停**（不再循环重试，避免一轮建一堆审批单）。

实测：`user` 模式批一次 →【不同命令】【跨会话】均放行（通配白名单 `tool='*'`）；`revoke` 后重新挂起；
批准 user 级单 → 通配白名单出现。

### 9.3 超级用户（`tenants.is_super`）

「拥有所有权限」：
- **免审批**：`Policy.check` 直接放行所有敏感工具；
- **免配额**：调用次数上限、磁盘/CPU/内存 quota 全部跳过。

隔离 / 网络 / 审计**仍照常生效**。设置：租户页「**超级用户**」勾选，或
`POST /api/tenants/{tid}/review` `{"action":"set","is_super":true}`。

## 10. 未做 / 后续

- **microVM 稳定性**：单次调用 + 端到端已跑通；长任务、并发、以及 `setcap`/socket 属组在
  **containerd 升级后需重设**，尚未长期验证。
- **MCP 按租户"配置"**：目前是"全局注册 + 调用时按租户放行"（已够用）；如需每租户各自的服务定义，要再加一层。
- **出口白名单的局限**：DNS 白名单**挡不住"直接用 IP 直连"**；要绝对强，用 `off`。
- **凭据走宿主代理**：当前靠"遮文件 + 不传 env"；如需沙箱内访问外部服务，应加宿主代理换凭据（Claude Code 的做法）。
- **每租户配额**：✅ 已做（见 §8）——剩下的是“配额用量展示”（前端显示已用/上限）。
- **运行记录清理**：`run_events` / `checkpoints.db` 无保留策略。
