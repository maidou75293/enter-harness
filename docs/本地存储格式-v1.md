# 本地存储格式 v1

> 本地后端有**三套**：**SQLite**（默认，四件套）、**Markdown**（人可读写的记忆 / 知识）、
> **PostgreSQL**（服务端 / 多副本，四件套）。
> 同一时刻只用一套，**不是双写、不是多份副本**。
> 命名遵循 `Harness-命名规范-v1.md`：`{Backend}{Concept}Port`。

## 1. 后端矩阵

| 端口 | SQLite | Markdown | PostgreSQL |
|---|---|---|---|
| `MemoryPort` | `StoreMemoryPort(SQLiteMemoryStore)` | `MarkdownMemoryPort` | `PostgresMemoryPort` |
| `KnowledgePort` | `SQLiteKnowledgePort` | `MarkdownKnowledgePort` | `PostgresKnowledgePort` |
| `StatePort` | `SQLiteStatePort` | 否（仍落 SQLite） | `PostgresStatePort` |
| `AuditPort` | `SQLiteAuditPort` | 否（仍落 SQLite） | `PostgresAuditPort` |

Markdown 后端仍使用 SQLite 存状态与审计；PostgreSQL 后端四件套全部落 PG。
`psycopg` 是可选依赖：`pip install 'agent-core[postgres]'`。
选择建议与 PostgreSQL 完整步骤见 `Harness-使用手册-v1.md`。

## 1.1 三种后端怎么选

| 场景 | 推荐 |
|---|---|
| 单机 / 本地开发 / 小数据 | SQLite |
| 人可读、可进版本库、少量人工维护 | Markdown |
| 多副本 / 服务端部署 / 并发写 | PostgreSQL |
| 审计合规 | SQLite 或 PostgreSQL，**不要 Markdown** |

## 2. 目录布局

```text
<root>/
├─ memory/                     # MarkdownMemoryPort
│  └─ <tenant_id>/<scope>/<scope_id>/<id>.md
├─ knowledge/                  # MarkdownKnowledgePort
│  └─ <tenant_id>/<scope>/<scope_id>/<id>.md
├─ memory.db                   # SQLite 后端
├─ knowledge.db
├─ state.db
└─ audit.db
```

- 空 `tenant_id` / `scope_id` 用 `_` 占位；
- 文件名用 `id` 安全化；非 ASCII 会追加 hash 后缀防碰撞；
- 正文是内容，frontmatter 是内核字段。

## 3. 记忆文件

```markdown
---
id: m_ab12cd34ef56
tenant_id: t1
kind: semantic
subtype: fact
scope: project
scope_id: p1
agent_id: ""
session_id: ""
key: 项目库
summary: ""
source: user
status: active
superseded_by: ""
created_at: 1710000000.0
updated_at: 1710000000.0
importance: 0.5
confidence: 0.6
condition: {"env": "DEV"}
provenance: [{"source": "user", "at": 1710000000.0}]
---

项目库是 gongxiang_dev。
```

读取规则：

- 只读取 frontmatter 里的 `MemoryRecord` 字段，未知字段忽略；
- 正文写入 `MemoryRecord.content`；
- **人改正文后，读时重算 `content_hash`**，下一轮缓存会失效；
- 非法文件跳过，不拖垮整体查询；
- `status` 为 `superseded` / `archived` 的文件保留，供审计回查。

写入规则：

- 先过 `validate_record`，非法返回 `invalid`，不落盘；
- 同 `(tenant, scope, scope_id, agent_id, kind, key, condition)` 只有一条 active；
- 同内容 → `noop` 并累加来源；
- 同 key 新内容 → 旧文件标 `superseded`，新文件写入，返回 `supersede`；
- 归档只改 `status`，不删文件。

## 4. 知识文件

```markdown
---
id: kb_ab12cd34ef56
tenant_id: t1
scope: project
scope_id: p1
doc_id: handbook-2026
title: 报销制度
source: handbook.md
content_hash: <正文 sha256>
review_status: approved
version: "2026-01"
created_at: 1710000000.0
updated_at: 1710000000.0
reviewer: admin
---

金额超过 5000 需要总监审批。
```

规则：

- 只有 `review_status: approved` 参与检索；
- **人改正文但未重新审核 → 自动退回 `pending`**，不会继续以旧审核放行；
- `archived` 不再可检索、不可再 approve；
- 无 `source` 不允许入库；
- 检索是本地关键词匹配（英文词 + 中文二元组），大数据量请换向量库适配器。

## 5. 工厂用法

```python
from agent_core.harness import build_local_ports

ports = build_local_ports("/data/agent", backend="markdown")
ports = build_local_ports("/data/agent", backend="postgres",
                          dsn="postgresql://user:pass@host:5432/db")
# 也可省略 dsn，读 HARNESS_PG_DSN / DATABASE_URL / PG* 环境变量
# ports.memory / ports.knowledge / ports.state / ports.audit
ports.close()
```

`build_local_ports` 只负责存储四件套；身份 / 上下文 / 行动 / 验收 / 审计出口
仍按 `PortSet` 由宿主装配。

## 6. PostgreSQL

连接：

```bash
pip install 'agent-core[postgres]'
export HARNESS_PG_DSN='postgresql://user:pass@host:5432/db'
# 也支持 DATABASE_URL，或 PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE
```

端口构造时自动执行 `CREATE TABLE IF NOT EXISTS` 与 `CREATE INDEX IF NOT EXISTS`；
账号需要目标 schema 的 `USAGE, CREATE`（PG 15+ 默认收回 public 的 CREATE）。

表（都带 `harness_` 前缀，不与业务表混用）：

| 表 | 用途 |
|---|---|
| `harness_memory` | 记忆记录；R1 用部分唯一索引 `WHERE status='active'` |
| `harness_knowledge_chunk` | 知识块；审核状态 + 来源 |
| `harness_run_state` | 线程最新状态 |
| `harness_run_checkpoint` | 检查点与 parent 链 |
| `harness_audit` | 审计哈希链 |

并发与一致性：

- 记忆 upsert 用 `pg_advisory_xact_lock` 按 `(tenant, scope, scope_id, agent, kind, key, condition)` 串行，避免同 key 并发插入撞唯一索引；
- 审计 `emit` 用固定 advisory lock 串行整条哈希链；
- 写入都在单事务内提交，失败回滚；
- `condition` / `provenance` / `state` / `extra` 用 `JSONB`。

## 7. 迁移与边界

- 当前没有 SQLite ↔ Markdown ↔ PostgreSQL 自动迁移命令；
- Markdown 适合新环境或人工维护的知识/画像；多副本不要共享 Markdown 目录；
- PostgreSQL 适合多副本；连接池由宿主负责，端口内是单连接 + 线程锁；
- Markdown 文件可进版本库，但**密钥、个人隐私不得写入**；
- 审计与状态不要用 Markdown 代替，哈希链与并发写不适用。
